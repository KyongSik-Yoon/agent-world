# 터미널 화면

pane 의 화면(`pane.read` 의 ANSI 줄들)을 브라우저에 다시 그린다. 코드는 `web/term.ts`(그리기·키 입력), `web/style.css` 의 `.term …`,
`server/control.ts` 의 `/api/term*`(읽기·흘려보내기), `server/termfont.ts`·`termtheme.ts`(ghostty 글꼴·색)에 있다.

고치기 전에 아래 두 가지를 먼저 한다. 거의 모든 헛수고가 이것을 건너뛰어 생겼다.

1. **실물 화면을 뜬다.** 스크린샷을 보고 짐작하지 말고 그 pane 의 줄을 읽는다(`herdr pane read --source visible --format text|ansi <pane>` — 읽기는 실제 세션에 해도 된다).
   깨진 줄의 칸 위치를 세어 본다. 상자 옆의 `[-]`, 오른쪽에 붙은 다른 창, 상태줄처럼 스크린샷에서는 안 보이는 것이 원인인 때가 많다.
2. **그 줄이 어떤 종류로 그려졌는지 본다.** 화면에서 `.tl` 의 클래스(`rule`·`grid`·`fit`·`panel`·`mascot`·`trailed`)를 읽으면 어느 갈래에서 틀렸는지 바로 나온다.
   그리는 코드를 고쳤는데 달라지지 않으면, 그 줄은 그 갈래로 오지도 않은 것이다(분류가 먼저 틀렸다).

## 두 가지 모드

| | 칸 지킴 | 줄 접기(`.term.flow`) |
|---|---|---|
| 어디서 | 넓은 화면·가로 휴대폰의 크게 보기 | 미리보기(작게 보기), 휴대폰 세로(폭 ≤ 760, portrait)의 크게 보기 |
| 글자 | pane 의 칸×줄을 창에 맞춘다. 하한 10px, 넘치면 옆으로 민다 | 10px 고정(미리보기와 같다), 줄을 접는다 |
| 까닭 | 크게 보기는 키가 pane 으로 가는 화면이라 칸이 맞아야 한다 | 좁은 폭에 칸을 지키면 못 읽는다 |

- 크게 보기 글자 하한은 어디서나 **10px**. 창 폭 760 기준 7px 안은 기각(7.5px 는 배율 1 화면에서 못 읽는다).
- 휴대폰 세로의 접은 글자도 10px 이다. 12px → 11px 을 거쳐 사용자가 10px 을 지정했다(12px 은 근거 없이 가져온 값이었다).
- 칸 지킴에서 pane 화면을 창의 폭·높이에 함께 맞출 때 어긋나는 비율은 **줄 높이**(`--term-line`, 1.1~1.3, 기본 1.22)로 받는다.
  자간을 벌리는 안은 사용자가 기각했고, 줄 수에 맞춰 글자를 줄이는 안은 양옆이 비었다. 하한 1.15 는 2536×1390(배율 1.5) 창에서 모자라 1.1 로 내렸다.
  pane 크기는 rect 에서 테두리를 뺀 값으로 넘긴다. 잴 때는 `hyprctl clients` 로 실제 창 크기부터 본다.

## 자판 입력

키 입력은 `TermKeys`(`web/term.ts`) 하나가 맡는다 — 숨은 입력란으로 키와 한글 조합을 받아 `/api/keys` 로 보낸다. 크게 보기와, 넓은 화면
가운데의 무대(`detail.ts` 의 `stageKeys`)가 함께 쓴다. 조합·조합 키 걸기·모아 보내기는 여기서만 고친다.

- **치는 데 칸 맞춤은 필요 없다.** 키는 바이트 그대로 pane 으로 가고, 커서는 pane 의 앱이 제 화면에 그린 글자다(우리는 커서를 그리지 않는다).
  그래서 무대는 줄을 접는 미리보기 그대로 입력을 받는다. 위 표의 "칸이 맞아야 한다"는 보기 좋으라는 까닭이지 입력의 조건이 아니다.
- 무대는 **화면을 눌러야** 입력을 받는다(테두리와 머리줄 글로 표시, 움직임 없음). 고르자마자 초점을 주면 섬의 글자 단축키(H·N·C·D·B)가 죽는다.
  놓기는 Shift+Esc, 바깥 누르기, 다른 주민 고르기. 그냥 Esc 는 pane 으로 간다(멈추기·대화상자 닫기에 쓰는 키다).
  무대에서 크게 보기는 머리줄 단추로만 연다 — 상태 창 안의 미리보기는 예전처럼 누르면 크게 보기다.
- 입력란은 무대에 붙박아 둔다. 미리보기 요소는 상태 창과 무대를 오가며 옮겨 붙어, 거기 두면 초점을 잃는다.
- 모아 둔 글자는 **친 때의 pane** 으로 간다(`pendingPane`). 무대는 고른 주민에 따라 pane 이 바뀌어, 보낼 때의 pane 으로 보내면 방금 고른 다른 주민에게 간다.
- 따라오는 속도는 미리보기 흐름 그대로다 — 서버가 입력 직후에는 읽기를 서두른다(`TERM_ECHO_MS`). 무대를 `live` 로 바꾸지 않는다(종일 떠 있는 화면이다).
- 지난 출력 넘기기(휠·PageUp)와 키 줄은 크게 보기에만 있다.
- 확인할 때: claude-in-chrome 의 Esc 누르기는 입력란에 닿지 않고 초점만 뺀다(페이지에 keydown 이 안 온다). Esc 는 `dispatchEvent` 로 본다.
  타일 창이 좁아 무대가 안 뜨면(좌우 창 사이 520px) `document.documentElement.style.zoom` 을 줄이고 `resize` 를 쏜다.

## 줄 접기에서 줄을 가르는 순서

`TermScreen.draw` 가 갱신마다 돈다. 줄 하나를 그리기 전에 묶음으로 먼저 가른다.

1. **세로로 나뉜 화면**(`stackPanes`): Claude 의 플랜 보기 창처럼 좌우로 나뉜 화면은 오른쪽 창을 위에, 왼쪽 창(대화+입력창)을 아래에 쌓는다.
   그대로 접으면 두 창의 글이 한 줄씩 섞인다. 오른쪽 창의 바탕색은 걷는다 — 줄마다 바탕이 깔리면 배너로 읽혀 … 로 잘렸다.
2. **상태줄 묶음**(`footerStart`): 입력창 아래의 상태줄. 8px 에 들어가면 한 줄로 맞추고(`.fit`), 넘치면 자르지 않고 긴 공백을 줄여 본문 크기로 접는다.
   사용자가 잘린 끝의 컨텍스트 비율을 보고 싶어 했다. 로고가 걸친 줄들은 한 줄(`.tl.mascot`)로 묶어 그림은 왼쪽에 통째로 세우고 글만 접는다.
3. **배너**(`bannerRanges`): 시작 배너만 8px 에서 … 로 자른다.
4. **상자 묶음**(`gridRanges`, `BOX_ROW`): 세로선·모서리로 시작하는 줄들. 여기서 다시 둘로 가른다(`isTable`).
   - **표**: 안쪽에 머리글 밑줄이나 칸 사이 세로선이 있다. 접지 않는다. 묶음째 같은 크기로 줄이고(`.grid`, 8px 까지) 그래도 넓으면 표만 옆으로 민다(값을 잃으면 안 된다).
   - **글 상자**(질문·플랜 승인 대화상자 등): 본문 크기로 들어가면 그대로, 넘치면 `panelLines` → `renderPanel` 로 접는다(`.tl.panel`).
5. 나머지는 `renderLine`. 상자 글자만 이어진 줄은 `.rule`(한 줄로 자르고 흐리게).

상자 묶음에서 모든 줄이 비어 있는 긴 칸 구간(8칸 넘게)은 3칸만 남기고 뗀다(`blankColumns`). pane 폭 가득 그린 상자가 화면 전체를 옆으로 밀던 것을 막는다.

### 글 상자(`.tl.panel`)

한 줄을 flex 칸 셋으로 나눈다: 왼쪽 세로선(`.hang`), 글(`.flowed`, 테두리 줄이면 `.run`), 오른쪽 테두리(`.edge`).

- 접힌 줄은 글 칸 안에서 이어지고, 양쪽 세로선은 접힌 높이만큼 내려온다. 목록이면 머리(`1.` `•`) 뒤 글자에 맞춰 들여 쓴다(`--mark`).
- 오른쪽 테두리는 화면 오른쪽 끝에 선다. 위·아래 테두리 줄(`FRAME_ROW`)은 양 끝 모서리를 둔 채 가운데 가로줄만 잘린다.
- 상자 폭 때문에 다음 줄로 넘긴 글은 앞줄에 다시 잇는다. 조건: 다음 줄 첫 낱말이 앞줄 끝에 안 들어감 + 같은 들여쓰기 + 목록 머리 아님 + **앞줄 끝과 다음 줄 첫 글자의 색·흐림이 같음**.
  색 조건이 없으면 "Show all · N more lines" 가 문단에 붙는다. 판단은 빈 칸을 떼기 **전**의 줄로 한다 — 뗀 줄로 하면 짧은 제목에 부제가 붙었다.
- 윗줄 옆에 상자 밖의 표시가 같은 줄에 놓일 수 있다(`╭───╮ [-]`). 창이 상자보다 넓으면 그 표시는 창의 오른쪽 끝으로 가서 모서리와 수십 칸 떨어진다.
  `BOX_ROW` 가 그 줄을 상자 줄로 읽어야 하고, `renderPanel` 은 표시를 제 줄로 올려 오른쪽에 붙인 뒤(`.tl.trailed`) 테두리를 닫는다.
  표시는 낱말 하나가 아닐 수 있다(desk-look 의 복사 상자: `╭───╮ ⧉ copy`). `BOX_ROW` 는 상자 글자가 없는 24자까지의 꼬리를 받는다.

## 글자를 그리는 법

- **상자·블록 문자는 글꼴 대신 칸에 직접 긋는다**(`.blk`). ─│╭╮┼ 와 ▀▄█▌ 를 글꼴로 그리면 줄 사이에 틈이 난다.
- **한글·전각은 두 칸**, 결합 문자는 칸으로 세지 않는다(`WIDE`·`JOINS`). 칸 수를 재는 곳은 반드시 `displayCols`·`splitColumns` 를 쓴다 — 문자열 길이로 자르면 한글 줄에서 어긋난다.
  그림 글자도 두 칸이다: ✅ ❌ 처럼 본래 그림으로 그리는 글자(`\p{Emoji_Presentation}`)와, 한 칸 글자 뒤에 VS16(U+FE0F)이 붙은 것(⚠️ ✔️).
  VS16 은 결합 문자처럼 0칸으로 세면 안 된다(`charCols`·`tokenCols`, `ANSI_TOKEN` 은 앞 글자와 한 조각으로 끊는다). 한 칸으로 세던 판에는 표에 ✅·⚠️ 가 든 줄마다
  뒤 칸이 하나씩 당겨져, 그 줄에서 나뉜 화면의 구분선을 못 찾고 두 창의 글이 섞였다.
- **세로선이 줄마다 어긋나는 것은 칸 눈금으로 푼다**(`cellFit`). 브라우저가 글 조각마다 폭을 1/64 기기 픽셀로 올리고 버려서 조각 많은 줄이 밀린다(304칸에서 0.4~2.2 기기 픽셀).
  글자의 실제 폭을 4000자 줄로 재서 `--cell` 과 자간으로 눈금에 맞추고, 크게 보기는 칸이 기기 픽셀 정수배가 되게 글자 크기를 조금 고친다(크기가 계단식으로 변하는 까닭).
  기각: 고정 자간(크기마다 오차 부호가 다르다), 글자 크기만 맞추기(글꼴 크기도 1/64 로 잘린다), 칸마다 absolute/`::before`(요소 2배).
  표·상태줄(`.grid`·`.fit`)은 제 크기를 CSS 가 정해 눈금을 안 쓴다 — 휴대폰 폭에서 0.2~0.64 기기 픽셀이 남아 있다(미수정).
- **배경 깔린 줄의 블록 실금**은 `.blk{position:relative}` 로 막는다. `overflow-y:clip` 은 줄 배경 사이에 실금을 만들어 기각.
- **글꼴과 색은 ghostty 설정을 따른다**(font-family·bold·variation·codepoint-map 을 읽어 `fc-match` 로 파일을 찾는다. 8MB 넘는 것·ttc 는 이름으로만).

## 스크롤

- **아래에 붙이기는 사용자가 손가락·휠로 올렸을 때만 푼다.** 스크롤 이벤트의 위치만 보고 풀면 브라우저가 스스로 낸 스크롤(자판 열고 닫기)에 풀려, 휴대폰에서 상태줄이 입력칸 밑에 숨었다.
  헤드리스로는 재현이 안 돼 `scrollTop -= 300` 과 뷰포트 높이 변경으로 흉내 냈다.
- **스크롤백 없는 에이전트(전체 화면 Claude Code)** 는 앱에 키를 보내 앱 화면을 넘긴다. 열 때 `/api/term/back` 으로 판별한다.
  Claude 만은 휠·끌기를 마우스 휠 신호(SGR `\x1b[<64/65;x;yM`)로 보내고 Ctrl+End(`\x1b[1;5F`)로 돌아온다. PageUp 은 0.35초에 한 쪽이라 끊겼다.
  Claude 는 몰아서 온 칸을 가속하므로(5칸 6줄, 20칸 67줄) 한 번에 5칸까지만 묶고 밀린 것은 10칸에서 자른다. 그 밖의 에이전트는 PageUp/PageDown.
  herdr 는 pane 이 마우스를 켰는지 알려 주지 않아, 실측한 Claude 에만 보낸다(전체 화면이 아닌 Claude 는 이 바이트를 버린다).
- **agy 는 한 번 위로 넘기면 스스로 내려오지 않는다**(1.5.13·1.5.14 실측). 새 출력이 쌓여도, 지시를 제출해도 그 자리에 머물고 입력창 바로 위에
  `↓ 1910 lines · 22 turns` 만 적는다 — pane 화면도 미리보기도 몇 시간 전 장면에 멈춘다. End·Ctrl+End(어떤 인코딩이든)는 안 먹고 PageDown·휠만 내린다.
  넘긴 횟수로 되돌리면(PageDown × 횟수+2) 넘긴 동안 쌓인 출력, 다른 pane 으로 옮기기, 새로고침에서 못 돌아온다. 그래서 그 표시를 상태로 읽어
  사라질 때까지 PageDown 을 보낸다(`server/agyscroll.ts`, `/api/term/bottom`). 지시를 보내기 전에도 내린다. 열 때 이미 넘겨져 있으면
  "지금 화면으로"만 띄우고 닫을 때 저절로 돌리지는 않는다(PC 앞에서 일부러 올려 둔 것일 수 있다). 크게 보기가 넘긴 것은 닫기·pane 옮기기·새로고침(`pagehide`)·휴대폰에서 앱을 내리거나 화면 끄기(`visibilitychange` hidden — 휴대폰은 이때 창을 닫지 않는다)에서 돌려 둔다. 1.5.14 는 넘겨 둔 동안 `pane read --source recent`
  한 번마다 3줄씩 더 올라간다(visible 은 안 움직인다). 표시는 대화 속 지시 위의 60칸 줄과 헷갈리지 않게, 아래에서 올라가며 찾은 입력창 윗줄 바로 위에서만 읽는다.
- 휴대폰의 크게 보기는 흐르는 화면을 초당 4번까지만 받는다(agy 처럼 표시가 쉬지 않고 도는 에이전트에서 발열).

## 증상으로 찾기

| 증상 | 볼 곳 |
|---|---|
| 상자 한 줄만 화면 끝까지 그어지거나 모서리가 열림 | 그 줄의 클래스가 `rule` 이면 `BOX_ROW` 가 놓쳤다. 줄 끝에 상자 밖 글(`[-]`)이 있는지 실물에서 본다 |
| 접힌 줄이 세로선 밖에서 시작, 오른쪽 세로선이 사라짐 | `panelLines`·`renderPanel`(`.hang`/`.edge`), `RIGHT_BORDER` |
| 선택지가 한 글자씩 세로로 쌓임 | 줄 안의 칸 이름이 바깥 창의 클래스와 겹쳐 그 배치 규칙을 물려받았다(`.body` 가 크게 보기 창의 본문과 겹쳤다 → `.flowed`). 새 칸 이름은 style.css 에서 먼저 찾아본다. 깊이 들여 쓴 줄은 `PANEL_HANG_MAX` |
| 두 창의 글이 한 줄씩 섞임 | `stackPanes` 가 구분선을 못 찾았다(`dividerCols`) — 먼저 그림 글자(✅ ❌ ⚠️)가 든 줄의 칸 수를 본다, 또는 상자에 든 표로 읽었다(`BOXED_OPEN`) — 왼쪽 창 안에서 닫힌 상자(대화상자·인용 상자)는 표로 세지 않는다. 그것만으로는 첫 칸이 좁고 가운데 칸이 자주 비는 표를 나뉜 화면으로 쌓아서, 세로선의 위나 아래가 모서리·이음매(┬ ┼ ┴ ╮)면 먼저 표로 친다(`TABLE_JOINT`). 세던 판에는 왼쪽 창의 상자 줄이 절반을 넘는 순간 섞였고, 줄이 흐르며 그 경계를 오가면 화면이 통째로 바뀌어 깜빡였다 |
| 표가 깨짐, 화면 전체가 옆으로 밀림 | `isTable` 판정, `.grid` 의 `--fit-cols`, `blankColumns` |
| 로고가 움직일 때 화면 아래가 깜빡임 | 상태줄 묶음(`.tl.mascot`)은 요소 하나를 계속 쓰고 바뀐 줄만 간다(`mascot`·`MascotBand`). 컷마다 묶음을 통째로 새로 만들던 판에는 그대로인 글 줄까지 다시 칠해졌다. 글 줄 앞에 딸려 오는 로고 칸의 색상 코드는 떼고 견준다 — 두면 컷마다 다른 줄로 안다 |
| 상태줄 로고가 조각남, 컷마다 글이 흔들림 | `unfoldFooter`·`mascot`. 로고 칸 폭은 그림이 아니라 **글이 시작하는 칸**으로 정한다(동작 컷마다 그림 폭이 다르고 빈 컷도 있다) |
| 선택지 커서 줄의 색·굵기가 아래 줄로 번짐(커서를 내리면 아래가 다 파랗다) | 줄 접기는 줄 끝 공백·색상 코드를 떼고(`trimTrailing`) 다음 줄은 앞줄 끝 스타일을 이어받는다. 뗀 꼬리의 `\e[0m` 은 `tailStyle` 로 반영해야 한다 — 빠지면 herdr 가 코드 없이 보내는 다음 줄들이 앞줄 색을 입는다 |
| 글이 … 로 잘림 | 배너로 읽혔다(`bannerRanges`) — 줄마다 바탕색이 깔린 묶음인지 본다 |
| 세로선이 줄마다 자글자글 | `cellFit` 이 걸리는 줄인지(`.grid`·`.fit` 은 안 걸린다) |
| 상태줄이 입력칸 밑에 숨음 | 아래에 붙이기가 풀렸다 — 무엇이 스크롤을 냈는지 |
| 미리보기가 갱신마다 위아래로 흔들림 | 미리보기 상자를 늘 채워 그리는지(줄 수가 갱신마다 달라지면 높이가 변한다) |

## 비용

그리기는 갱신마다 돈다. 줄 단위 변환은 Row 에, 묶음 단위 변환은 묶음 key(`boxForms`)로 기억해 둔다 — 매번 다시 계산하던 판에 휴대폰 크게 보기가 7.4 → 9.6ms 로 늘었고, 기억해 두자 3.9ms 가 됐다.
나뉜 화면을 쌓는 `stackPanes` 도 같다. 줄마다 재는 것(색상 코드를 뺀 글, 구분선 칸, 가른 양쪽)을 줄의 글로 기억한다(`paneLines`) — 기억하지 않던 판에는 플랜 옆 창이 뜬 넓은 pane(302칸 × 85줄)의 미리보기가 한 줄만 바뀌어도 2ms 가 아니라 13.5ms 를 썼다.
상태 창은 스냅샷마다 본문을 새로 짓지만 미리보기를 품은 칸(질문 카드, 터미널 화면 칸)은 내용이 같으면 그대로 둔다(`detail.ts` 의 `asked`·`screened`) — 새로 지으면 미리보기가 떼였다 붙어 스크롤이 0 으로 갔다 돌아온다.
새 변환을 넣으면 Row 의 `key` 에 그 입력이 다 들어가는지 본다(빠지면 옛 그림이 재사용된다). web/ 을 바꿨으니 `ui-perf` 스킬대로 `bun run perf` 를 돌린다.

## 확인하는 법

- **실물로 본다.** 그 화면이 지금 떠 있으면 고친 판을 읽기 전용으로 띄워 실제 세션을 본다(임시 `XDG_STATE_HOME`, 드문 포트, 스스로 끝나게).

  ```sh
  XDG_STATE_HOME=<임시> AGENT_WORLD_READONLY=1 AGENT_WORLD_PORT=<드문 포트> timeout 900 bun server/index.ts
  ```

  켜져 있는 크롬 탭(claude-in-chrome)으로 열어 주민을 고르면, 넓은 화면에서도 상태 창의 미리보기는 줄 접기(348px 안팎)로 그려진다. 휴대폰 폭을 따로 만들지 않아도 접는 갈래는 여기서 다 볼 수 있다.
  미리보기는 아래에 붙어 있으니 휠로 올려서 본다.
- **좌표로 잰다.** 눈으로만 보지 말고 `.tl` 의 클래스와 `.hang`·`.edge` 의 `getBoundingClientRect()` 를 뽑아, 테두리 줄과 본문 줄의 오른쪽 끝이 같은지 본다.
- **화면이 없으면 만든다.** Claude 의 표·대화상자는 격리된 aw-test 세션에 `claude --model haiku "<출력 지시>"` 를 띄워 `pane read --format ansi` 로 뜬다. 이 저장소 세션의 화면은 플러그인이 중간 글을 요약해 원문이 안 남는다.
- **배율·휴대폰 폭을 재야 하면** 헤드리스 크롬 + CDP 의 `Emulation.setDeviceMetricsOverride` 를 쓴다(타일 창은 크기를 못 바꾼다. 드문 포트, 붙기 전에 비었는지 확인). 페이지는 iframe 에 못 넣는다.
- **가려진 탭은 rAF 가 초당 1번**이라 반응 속도를 못 잰다. 요청 흐름(`/api/keys` + `/api/term` SSE)을 스크립트로 흉내 내 잰다.
- **그리기 비용을 견줄 때**: `dev/mock-herdr.ts` 는 화면을 한 번만 읽는다. `screens.clear()` 를 넣은 사본과 시나리오를 250ms 마다 고쳐 쓰는 스크립트로 갱신을 흉내 내고, 옛·새 빌드를 트레이스(FireAnimationFrame p50/p95)로 견준다. 같은 그림인지는 두 빌드의 `.tl` 클래스·글을 떠서 비교한다.
- 시험 서버를 끌 때 `pkill -f` 를 쓰지 않는다. pid 와 `/proc/<pid>/cwd` 를 보고 끈다.
